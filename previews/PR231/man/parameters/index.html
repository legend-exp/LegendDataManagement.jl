Parameters and Property Files

Analysis results such as calibration constants are stored as JSON or YAML property files in the parameter directories par and jlpar of a LegendData object. This page describes how these files are read and written (readlprops, writelprops), how units and uncertainties are encoded, how the files are organized in l200.par, and how a validity.yaml file selects the files that apply at a given time.

Layout of the Parameter Directory

l200.par is a LegendDataManagement.PropsDB for the directory configured as par (see Configuration and LegendData); l200.jlpar does the same for jlpar. The Juleana dataflow organizes the directory in two trees, each with one sub-directory per parameter category (ecal, ctc, pz, aoe, psd, qc, sipmcal, ...):

  • rpars (run level): one file per run, rpars/<category>/<period>/<run>.yaml, holding the parameters of all detectors of the run.
  • ppars (partition level): one directory per detector, ppars/<category>/<detector>/<partition>.yaml, holding the parameters of one detector for all runs of a partition.

The directories are created when the first file is written. The parameter directory of the documentation test production is empty at the start of this page, so the examples write their own parameters. A path that does not exist yet is a LegendDataManagement.NoSuchPropsDBEntry, a placeholder that can be written to; further indexing extends the path.

using PropDicts, Unitful, Measurements

typeof(l200.par.rpars.ecal)
LegendDataManagement.NoSuchPropsDBEntry

Reading and Writing Property Files

readlprops reads a JSON or YAML file into a PropDicts.PropDict, writelprops writes one. The file format follows the file name extension. Both functions convert between the stored fields val, err and unit and Julia objects:

  • val and unit become a Unitful.Quantity.
  • val and err become a Measurements.Measurement.
  • val, err and unit become a Unitful.Quantity of a Measurements.Measurement.
  • An entry with only unit becomes a NaN with that unit, and a null value of err becomes a NaN uncertainty.
  • The units none, ADC, adc and sample and an empty unit are unitless; e is the atomic unit of charge and % is percent. All other units are parsed by Unitful.jl and UnitfulAtomic.jl; an unknown unit throws an ArgumentError.
  • Arrays are converted element by element. All other entries are unchanged.

A PropDict with quantities and measurements is written as follows.

props = PropDict(
    :tau => 40.0u"μs",
    :fwhm => 2.5u"keV" ± 0.1u"keV",
    :ratio => 0.5 ± 0.01,
    :name => "example",
)

dir = mktempdir()
file = joinpath(dir, "example.yaml")
writelprops(file, props)
print(read(file, String))
name: "example"
ratio:
  val: 0.5
  err: 0.01
fwhm:
  unit: "keV"
  val: 2.5
  err: 0.1
tau:
  unit: "μs"
  val: 40.0

Reading the file restores the objects.

readlprops(file)
PropDicts.PropDict with 4 entries:
  :name  => "example"
  :ratio => 0.5±0.01
  :fwhm  => 2.5±0.1 keV
  :tau   => 40.0 μs

A file written by hand follows the same conventions. The entry resolution below has an undefined uncertainty, and dead has a unit but no value.

write(joinpath(dir, "hand.yaml"), """
resolution:
  val: 2.5
  err: null
  unit: keV
offset:
  val: 1
  unit: ADC
dead:
  unit: ms
""")

readlprops(joinpath(dir, "hand.yaml"))
PropDicts.PropDict with 3 entries:
  :offset     => 1
  :dead       => NaN ms
  :resolution => 2.5±NaN keV

readlprops also accepts a vector of file names and merges the files in order, so that later files take precedence. JSON cannot hold NaN: writing a PropDict with a NaN to a .json file throws an ArgumentError, while YAML files store it as .NaN.

Keys named `val`

writelprops and readlprops interpret every entry that has the field val together with unit or err as a value. A configuration file that gives another meaning to such a key is altered by a read and write cycle.

Values and Uncertainties

get_values and get_uncertainties split the measurements of a PropDict or an array. get_values removes the uncertainty of every Measurement and keeps the unit; get_uncertainties returns the uncertainty with the unit. Entries that are not measurements are returned unchanged by both.

get_values(readlprops(file))
PropDicts.PropDict with 4 entries:
  :name  => "example"
  :ratio => 0.5
  :fwhm  => 2.5 keV
  :tau   => 40.0 μs
get_uncertainties(readlprops(file))
PropDicts.PropDict with 4 entries:
  :name  => "example"
  :ratio => 0.01
  :fwhm  => 0.1 keV
  :tau   => 40.0 μs

lstring returns the single-line JSON text of a PropDict as written by writelprops.

lstring(PropDict(:fwhm => 2.5u"keV", :n => 2))
"{\"n\":2,\"fwhm\":{\"unit\":\"keV\",\"val\":2.5}}"

Writing Parameters

writelprops(db, key, props) writes the file <key>.yaml into the directory of a LegendDataManagement.PropsDB or NoSuchPropsDBEntry db and creates the directory if necessary (see data_path). Indexing with a period or a detector selects the sub-directory. A run-level parameter file is written with the period as the directory and the run as the key:

ecal = PropDict(:V99000A => PropDict(:e_cusp => PropDict(:cal => PropDict(
    :func => "e_cusp * 0.25keV + 1.5keV", :fwhm => 2.5u"keV" ± 0.1u"keV"))))

writelprops(l200.par.rpars.ecal[DataPeriod(2)], DataRun(6), ecal)
readdir(data_path(l200.par.rpars.ecal))
1-element Vector{String}:
 "p02"

Indexing a database with two keys reads the file <first>/<second>.yaml without any validity selection and returns a PropDict. The keys are symbols or data selectors.

l200.par.rpars.ecal[DataPeriod(2), DataRun(6)]
PropDicts.PropDict with 1 entry:
  :V99000A => PropDict(:e_cusp=>PropDict(:cal=>PropDict(:func=>"e_cusp * 0.25ke…
l200.par.rpars.ecal[:p02, :r006] == l200.par.rpars.ecal[DataPeriod(2), DataRun(6)]
true

The partition level works in the same way with the detector as the directory and the partition as the key; the Juleana processors write ppars/<category>/<detector>/<partition>.yaml with writelprops(l200.par.ppars.ecal[det], part, props).

Validity

A directory of a LegendDataManagement.PropsDB may contain a file validity.yaml that states which files apply from which time on, separately for each data category. The parameter databases use the same mechanism as the metadata, described in Metadata and Validity. An entry has the fields valid_from (a timestamp), category (default all), apply (a file name or a list of file names relative to the directory) and mode. The modes are reset (the list of files is replaced), append, remove and replace (the two files are the one to remove and the one to add). The first entry of a category is always a reset.

LegendDataManagement.LDMUtils.writevalidity adds such an entry at the start time of a FileKey; mfk below is a file key of the production in the test metadata (period 2, run 6, category cal). The (period, run) form applies the file <period>/<run>.yaml, a DataPartition the file <partition>.yaml.

using LegendDataManagement.LDMUtils

writevalidity(l200.par.rpars.ecal, mfk, (DataPeriod(2), DataRun(6)); category = :cal)
print(read(joinpath(data_path(l200.par.rpars.ecal), "validity.yaml"), String))
- valid_from: "20221226T200846Z"
  apply:
    - "p02/r006.yaml"
  category: cal
  mode: "reset"

The database is then called with a FileKey, a LegendDataManagement.ValiditySelection or a timestamp and a category. The files that are valid at that time and for that category are read and merged into one PropDict.

l200.par.rpars.ecal(mfk)
PropDicts.PropDict with 1 entry:
  :V99000A => PropDict(:e_cusp=>PropDict(:cal=>PropDict(:func=>"e_cusp * 0.25ke…
l200.par.rpars.ecal("20230101T000000Z", :cal) == l200.par.rpars.ecal(mfk)
true

The first two indices can also select the tree and the category: l200.par[:rpars, :ecal](mfk) is l200.par.rpars.ecal(mfk). Juleana code selects the tree with a variable, for example l200.par[pars_type, :pz](filekey) with pars_type either :rpars or :ppars.

A selection before the first entry of the category throws an ArgumentError, and a category without an entry (and without an entry for all) throws an ErrorException.

try
    l200.par.rpars.ecal(ValiditySelection("20210101T000000Z", :cal))
catch err
    println(sprint(showerror, err))
end
ArgumentError: Selected validity date 20210101T000000Z is before first available validity date 20221226T200846Z for category :cal
try
    l200.par.rpars.ecal(ValiditySelection("20230101T000000Z", :phy))
catch err
    println(sprint(showerror, err))
end
No validity entries for category phy or category all

Partitions

In a partition-level database, the validity file of a detector lists one entry per run of the partition, all applying the partition file. LegendDataManagement.LDMUtils.get_partitionvalidity returns the start file key of each run and the validity file name for a detector and a partition:

part = first(keys(partitioninfo(l200, :V99000A, :cal)))
validity = get_partitionvalidity(l200, :V99000A, part)
first(validity, 2)
2-element Vector{@NamedTuple{period::DataPeriod, run::DataRun, filekey::FileKey, validity::String}}:
 (period = DataPeriod(2), run = DataRun(0), filekey = FileKey("l200-p02-r000-cal-20220101T000000Z"), validity = "V99000A/calpartition001a.yaml")
 (period = DataPeriod(2), run = DataRun(1), filekey = FileKey("l200-p02-r001-cal-20220201T000000Z"), validity = "V99000A/calpartition001a.yaml")

Writing the parameters and the validity of the partition takes one call of writelprops and one call of LegendDataManagement.LDMUtils.writevalidity for each run:

db = l200.par.ppars.ecal[:V99000A]
writelprops(db, part, PropDict(:e_cusp => PropDict(:fwhm => 2.0u"keV")))
for run in validity
    writevalidity(db, run.filekey, part; category = :cal)
end
l200.par.ppars.ecal[:V99000A](mfk)
PropDicts.PropDict with 1 entry:
  :e_cusp => PropDict(:fwhm=>2.0 keV)

The processors of the dataflow use the wrappers write_pars and write_validity of Juleana.jl (see Use in Juleana.jl), which call these functions.

Overrides

If the metadata directory contains jldataprod/overrides/par (or jlpar), the files in it take precedence over files of the same name in the parameter directory, and its validity.yaml entries are merged with those of the parameter directory. l200.par reads the override directory but writes only to the directory configured as par.
