LegendDataManagement.DetectorId — Type
struct DetectorId <: DataSelector

Represents a LEGEND detector ID.

Detector IDs are stored encoded as an UInt32 internally. They can be created from their string or Symbol representation or from the encoded integer.

Fields

  • _encoded::UInt32: Binary encoding of the detector ID.

Examples

using LegendDataManagement

detector = DetectorId(:V99000A)
string(detector) == "V99000A"
DetectorId("V99000A") == detector
UInt32(detector)  # returns the binary encoding

Encoding

The following 32-bit unsigned integer encoding is used for LEGEND detector IDs.

Binary encoding

Encoding length: 4-byte unsigned integer value, stored as a 32-bit or 64-bit integer.

Format (nibbles): RT XX XX XY

  • Reserved (R): 1 Nibble, always zero

  • Type (T), 1 Nibble:

    • 0x0: reserved
    • 0x1: C (Coax HPGe)
    • 0x2: B (BEGe HPGe)
    • 0x3: P (PPC HPGe)
    • 0x4: V (ICPC HPGe)
    • 0x5: reserved
    • 0x6: reserved
    • 0x7: reserved
    • 0x8: reserved
    • 0x9: S (SiPM)
    • 0xa: PMT (PMT)
    • 0xb: PULS
    • 0xc: AUX
    • 0xd: DUMMY
    • 0xe: BSLN
    • 0xf: MUON

  • Serial-Number (XXXXX), 5 Nibbles, unsigned integer in binary form (not BCD).

  • Sub-Serial-Number (Y), 1 Nibble, unsigned integer in binary form (not BCD):

    • For HPGe: Detector slice, 0 = A, 1 = B, 2 = C, ...
    • For SiPM: always 0
    • For PMT: always 0
    • For Pulser: 0 = PULSnn, 1 = PULSnnANA
    • For Dummy: always 0

String representation

  • [B|C|P|V]nnnnn[A-P]: represent serial number with five digits in string, followed by the slice letter
  • Snnn: represent serial number with three digits in string
  • PMTnnn: represent serial number with three digits in string
  • PULSnn, PULSnnANA: represent serial number with two digits in string
  • AUXnn: represent serial number with two digits in string
  • DUMMYnn: represent serial number with two digits in string. Special case: legacy data may contain DUMMY0 to DUMMY9, with a single digit, it should be possible to parse these as well, but when converting integer to string representation, two digits should be used.
  • BSLNnn: represent serial number with two digits in string
  • MUONnn: represent serial number with two digits in string

Special cases

  • C00ANGn: Encode as R[C][f100n][0]
  • C000RGn: Encode as R[C][f200n][0]

LegendDataManagement.LegendData — Type
struct LegendData <: AbstractSetupData

LegendData(setup::Symbol; dataset::Symbol = :default)
LegendData(setup_config::SetupConfig, name::Symbol, dataset::Symbol)

Provides access to LEGEND data and metadata.

LegendData(setup; dataset) requires the $LEGEND_DATA_CONFIG environment variable to be set (see LegendDataConfig) and uses the SetupConfig of setup. dataset names the run list in the metadata datasets/runlists that runinfo and analysis_runs read; :default selects no run list, so runinfo holds every run the metadata has.

LegendData has the (virtual) properties

  • metadata: The metadata database as a LegendDataManagement.PropsDB.
  • par: The parameter database par as a LegendDataManagement.PropsDB.
  • jlpar: The parameter database jlpar as a LegendDataManagement.PropsDB.
  • tier: A LegendDataManagement.LegendTierData that gives the paths of the data files.
  • name::Symbol: Name of the setup.
  • dataset::Symbol: Name of the dataset.

Examples

using LegendDataManagement

config_filename = "/path/to/config.json"
config = LegendDataConfig(config_filename)
l200 = LegendData(config.setups.l200, :l200, :default)

or simply (if $LEGEND_DATA_CONFIG is set):

l200 = LegendData(:l200)

The full path to tier data files can be retrieved using l200.tier:

l200.tier[:raw]
l200.tier[:raw, FileKey("l200-p02-r006-cal-20221226T200846Z")]

LegendData comes with an extension for SolidStateDetectors.jl:

using SolidStateDetectors

l200 = LegendData(:l200)

LegendDataManagement.PropsDB — Type
struct LegendDataManagement.PropsDB

A PropsDB instance, e.g. myprops, presents an on-disk directory containing JSON or YAML files or sub-directories (that contain such files in leaf directories) as a dictionary of properties.

PropsDB supports Base.keys and Base.getindex as well as Base.propertynames and Base.getproperty to access its contents. getindex and getproperty return either another PropsDB or a PropDicts.PropDict, depending on whether the accessed property is stored as a sub-directory or a file. getproperty is meant for properties/keys that are more or less standardized, getindex for arbitrary ones (see examples below).

The contents of PropsDB may be time- and category-dependent, determined by the presence of a validity.yaml file. In this case, use myprops(sel::LegendDataManagement.ValiditySelection), myprops(timestamp, category) or myprops(filekey::FileKey) to select the desired time and category. The selection can be made at some point during traversal of properties or at the leaf PropsDB (see the examples below).

Code that uses PropsDB should not instantiate it directly. Use LegendDataManagement.AnyProps(path::AbstractString) instead, which returns the PropsDB for the directory path.

Parametric types

  • VS: Nothing if no validity selection has been made, otherwise LegendDataManagement.ValiditySelection.

Examples

using LegendDataManagement

l200 = LegendData(:l200)

propertynames(l200.metadata.hardware)
l200.metadata.hardware.detectors.germanium

keys(l200.metadata.hardware.detectors.germanium.diodes)

channelinfo(data::LegendData, sel::AnyValiditySelection; kwargs...)

Returns the channel information of data for the selection sel as a TypedTables.Table with one row per channel.

sel is a LegendDataManagement.ValiditySelection or a FileKey, a run (period, run, category), a run (period, run), a period (period, category) or a period. A selection that names no category uses :cal; a period alone selects (period, :cal). The selections can also be passed as separate arguments, e.g. channelinfo(data, period, run, category).

Keywords

  • system::Symbol = :all: Keep only the channels of this system, e.g. :geds or :spms. :all keeps every system.
  • only_processable::Bool = false: Keep only channels that are marked as processable.
  • only_usability::Symbol = :all: Keep only channels with this usability, e.g. :on. :all keeps every usability.
  • sort_by::Symbol = :detector: Name of the column to sort by, compared as strings. :string sorts by detector string and position. A name that is not a column leaves the order of the channel map.
  • extended::Bool = false: Add the columns cc4, cc4ch, daqcrate, daqcard, hvcard, hvch, enrichment, mass, total_volume, active_volume and fccd.
  • verbose::Bool = true: Warn if the metadata has no FCCD value of a detector with extended = true; the FCCD is then set to zero.
  • only_analysis_runs::Bool = true: For a period selection, merge only the analysis runs.
  • explode_partitions::Bool = false: Return one row per detector and partition.

Columns

The table has the columns detector, channel, fcid, rawid, system, processable, usability, is_blinded, psd_usability, low_aoe_status, high_aoe_status, lq_status, ann_status, coax_rt_status, is_bb_like, partition, det_type, location, detstring, fiber and position, plus the columns listed for extended.

For a period selection (period, category) the channel information of all runs of that category in the period (only the analysis runs if only_analysis_runs) is merged into one table: the status columns processable, usability, is_blinded, psd_usability and the PSD *_status columns take the best value over the runs, all other columns must be identical in every run.

The column partition is taken from partitioninfo. For a period selection (period, category) it holds the sorted DataPartitions of each detector that contain the period, empty for a detector in no partition. For every other selection it holds the one DataPartition of each detector that contains the run, missing for a detector in no partition. If the metadata has no groupings of the category (datasets/<category>_groupings), partition is missing for every detector. With explode_partitions = true the table has one row per detector and partition, with a single DataPartition in partition; detectors in no partition are left out.

The result is cached per data object and selection, so changes of the metadata on disk are not seen by the same data.

LegendDataManagement.read_ldata — Function
read_ldata(data::LegendData, selectors...; kwargs...)
read_ldata(f, data::LegendData, selectors...; kwargs...)

read_ldata(columns::NTuple{<:Any, Symbol}, data::LegendData, selectors::Tuple; kwargs...)
read_ldata(column::Symbol, data::LegendData, selectors::Tuple; kwargs...)

Reads lh5 data from disk for a given set of selectors.

After reading in, a PropertyFunction f can be applied to the data. If a tuple of Symbols is given, the properties from the tuple are selected; a single Symbol selects one property. det is a DetectorId. The selectors are a tier followed by a file key, a vector of file keys or timestamps, or a data category with a period, a run, a partition or a run table, optionally followed by a detector or a vector of detectors.

The methods that read data are provided by an extension that is loaded together with LegendHDF5IO.jl; without it the call throws an ErrorException. The extension is described in the docstring of the method for (tier, filekey, timestamps, det) selectors.

A vector of Unitful.Time timestamps in place of a FileKey reads only the rows with those timestamps, in time order: each is looked up with find_filekey in the DAQ cycle that contains it, and only those rows of the cycle's file are read. The time of a row is its timestamp column, or tstart in an event tier. A table without one of the timestamps is an error, or is skipped with ignore_missing. With a FileKey and the timestamps, (tier, filekey, timestamps, det), the cycle is given instead of looked up and the rows follow the timestamps.

The filterby kwarg takes a PropertyFunction selecting rows of the tier being read. Given a tier => PropertyFunction pair instead, the function is evaluated on tier and the resulting row selection is applied to the tier being read. Both tiers must hold one row per trigger of the same detector, so that their rows correspond by position; a row-count mismatch raises a DimensionMismatch.

A run, given by category, period and run or through a period, partition or run table, is read from the file keys listed for it in the metadata, only(runinfo(data, (period, run, category)).keys); a listed file key that is not on disk is an error. The keywords search_disk and ignore_keys control which file keys these are. A run with no file keys left is an error. A per-run file of the detector, data.tier[tier, category, period, run, det], holds the whole run and is read in place of the file keys whenever it exists.

Keywords

  • filterby = nothing: A PropertyFunction, or a tier => PropertyFunction pair, that selects the rows to read.
  • ignore_missing::Bool = false: Skip a table that is missing or has no row for a requested timestamp instead of throwing an error.
  • parallel::Bool = false: Read the file keys, timestamp cycles or runs in parallel on the workers of wpool.
  • wpool::WorkerPool = default_worker_pool(): Worker pool for parallel = true.
  • search_disk::Bool = false: For a run, read the file keys found on disk with search_disk(FileKey, data.tier[tier, category, period, run]) instead of those listed in the metadata.
  • ignore_keys::Symbol = :all: For a run, drop the file keys that bad_filekeys returns with load_key = ignore_keys, i.e. those listed under ignore_keys in datasets/ignored_daq_cycles, or under any of its keys for :all. :none keeps every file key.

Reads lh5 data of data; the methods are provided by the extension for LegendHDF5IO.jl. See read_ldata for the arguments, keywords and examples.

The selectors, as a tuple or as separate arguments, can have the forms

  • (tier, filekey), (tier, filekey, det): one DAQ cycle, all channels or one detector.
  • (tier, filekey, timestamps), (tier, filekey, timestamps, det): the rows of one DAQ cycle with the given times.
  • (tier, timestamps), (tier, timestamps, det): the rows with the given times, each read from the DAQ cycle that contains it.
  • (tier, filekeys), (tier, filekeys, det): several DAQ cycles.
  • (tier, category, period), (tier, category, period, det), (tier, category, period, run), (tier, category, period, run, det): runs of a period or a run.

Creates a Simulation from LEGEND metadata.

The simulation is built from the diode metadata and, if available, the crystal metadata, with the LEGEND defaults, such as the ADLChargeDriftModel2016. T is the floating-point type, Float32 if it is not given. The extension is loaded together with SolidStateDetectors.jl.

Arguments

  • data::LegendData: LEGEND data structure containing metadata.
  • detector::DetectorIdLike: Identifier of the detector. The crystal metadata is taken from the crystal named after the detector without its last character.
  • diode_filename::String: Path to the diode metadata file.
  • xtal_filename::String: Path to the crystal metadata file.
  • diode_meta::PropDict: Diode metadata as a PropDict.
  • xtal_meta::Union{PropDict, LegendDataManagement.NoSuchPropsDBEntry}: Crystal metadata as a PropDict, or NoSuchPropsDBEntry if not available. Without crystal metadata a warning is printed and a constant impurity density of zero is used.
  • env::HPGeEnvironment = HPGeEnvironment(): Environment of the detector, by default a vacuum cryostat at 78 K (see HPGeEnvironment).

Keywords

  • operational_voltage::Number: Operating voltage of the n+ contact in V. Accepts units; a number without units is interpreted as V. If not provided, the recommended voltage of the L200 characterization or of the manufacturer from the metadata is used, otherwise 5000 V.
  • n_thickness::Number: Thickness of the n+ contact in mm. Accepts units; a number without units is interpreted as mm. If not provided, the FCCD of the 0νββ analysis or the manufacturer's value from the metadata is used, otherwise 1 mm.
  • use_impurity_corrections::Bool = true: Apply the corrections (scale, offset) of the impurity curve of the crystal metadata.
  • allow_cylindrical_asymmetry::Bool = true: Whether to allow geometry features that break the cylindrical (azimuthal) symmetry of the detector, such as a crack defined in the metadata geometry.extra. When true and such a feature is present, the affected volume is cut from the semiconductor and contacts and the simulation grid is switched to a full 3D azimuthal range (phi from 0 to 360). When false, these features are ignored and the simulation remains 2D (azimuthally symmetric).
  • verbose::Bool = true: Print the values that are used for the thickness, voltage and impurity density, and whether they are defaults.
  • ssd_config_filename::Union{Missing, AbstractString} = missing: If given, write the SSD configuration to this YAML file.
  • dicttype = OrderedDict{String,Any}: Dictionary type of the SSD configuration.

Examples

using LegendDataManagement, SolidStateDetectors

l200 = LegendData(:l200)
sim = Simulation(l200, :V99000A)
calculate_electric_potential!(sim)
